## 1. 핵심 흐름 (소유자 정의, 2026-09-29)

| 단계 | 핵심 역할 | 되돌려 보낼 수 있는 주체 |
|---|---|---|
| 이슈 생성 | 사용자 + KTB 스킬 | — |
| plan | 여러 역할의 관점으로 계획 | — |
| implement | builder 구현, verifier가 테스트의 증명력 확인 | verifier의 거부 |
| review | 여러 역할이 각자의 관점으로 리뷰 | 리뷰어의 must_fix |
| gate | 테스트와 리뷰가 모두 통과할 때까지 차단 | 실패한 테스트 |
| merge | 통과한 것을 머지 | — |

plan과 review의 다중 역할, verifier는 핵심이다. 줄이지 않는다.

## 2. 원칙

- **P1.** 작업을 되돌려 보낼 수 있는 것은 셋뿐이다: 실패한 테스트, 리뷰어의 must_fix, verifier의 거부.
  다른 장치는 기록만 남긴다. 예외는 이 문서에 이름으로 적는다(§4 "차단 유지").
- **P2.** 부가 장치는 흐름 안에서 LLM 세션을 쓰지 않는다.
- **P3.** 되돌아갈 때 새 잡·새 세션으로 처음부터 시작하지 않는다.
- **P4.** 끝난 세션의 산출물을 부가 장치의 사유로 버리지 않는다.

## 5. 작업 순서

기록으로 내리는 장치는 **스위치로** 만든다(`harness.toml`의 장치별 `enforce = "block" | "record"`). 기본값을 `record`로 바꾸되
`block`으로 되돌릴 수 있다. 제거가 아니므로 코드는 남고, 기록은 계속 쌓여 나중에 다시 판단할 수 있다.

| Phase | 내용 | 기대 효과 | 의존 |
|---|---|---|---|
| 0 | 아티팩트 범위 수정(L41) 배포 → 1.4.33 | 잡이 success로 끝남, 유출 중단 | 미러 갱신 |
| 1 | **멈추지 않게**: #56 #51 #52 #40 #57 #48 #54 #10 #22 #82(에스컬레이션)을 기록으로, #55 #35 제거 | 부가 장치 멈춤 110런 중 약 40런 | 결정 1 |
| 2 | **러너 큐**: #80 제거, #81을 잡 안으로, #83 #86 #87을 스테이지 러너 밖으로, #72 재사용 | 런 1,884 → 수백, 대기 시간 | — |
| 3 | **같은 런 안에서 되돌림**: 게이트 RED·verifier 거부 시 같은 빌더 세션에서 수리. flaky 분류(#43) 수리 | implement 재실행 감소 | Phase 1 |
| 4 | **세션 수**: 오케스트레이터 대체 가능성 조사 → 설계. R1 판정을 기록에 남겨 R2-light 측정 | 스테이지당 세션 1개 | 결정 2, 4 |
| 5 | **운영 세션 절차**: 감시는 스크립트, 결함 수정은 이슈당 새 세션 | 컨트롤러 토큰 | — |

넘는 Phase(1, 2)는 장치 단위 태스크로 나눈다.

## 8. v2 — 토론 뒤 개정 (2026-09-29)

v1은 쓰인 대로 실행하지 않는다. 세 입장이 2라운드에서 아래로 수렴했다.

### 8.1 v1에서 틀렸던 것

| v1의 주장 | 판정 | 근거 |
|---|---|---|
| Phase 1이 멈춤 약 40런을 없앤다 | **철회** | 그 멈춤 31건 중 30건은 이미 배포된 수정 이전에 일어났다. 미래 절감은 0이 아니라 미측정이다 |

| Fix 루프(#67)는 같은 세션 안 되돌림이다 | **틀림** | `factory-implement.js:568-595`는 새 builder 세션을 띄운다. 엔진에 세션을 재개하는 코드는 없다 |

### 8.2 토론이 찾은 구조 문제

1. **세션이 재사용되지 않는다.** own-calendar 캠페인 창 712세션 중 399개(56%)가 같은 이슈·같은 역할의 반복 세션이고
   캐시 읽기의 62.5%를 쓴다. 반복 builder는 첫 세션과 같은 턴 수(중앙값 67 대 64)를 돈다.
2. **가장 비싼 되돌림은 핵심의 것이다.** 리뷰 rework는 새 잡 2개와 큐 대기 2회를 만든다(18런 $114). v1의 Phase 3 범위 밖이었다.
3. **검사 장치는 자기 결함률을 갖는다.** 플랜 검증기는 27시간에 서로 다른 결함 4개, prove-test는 6개를 냈다. 결함 하나의
   수리는 컨트롤러 토큰 약 40M(881M ÷ 수정 PR 22건)이다.
4. **구조를 바꿔도 장치 결함의 대부분은 남는다.** L12–L40 중 단일 잡 구조가 없애는 것은 5건 안팎(L20·L21·L40·sweeper 오판)이고
   나머지는 검사 로직의 결함이다. 전면 재작성은 토큰으로 회수되지 않는다(회수까지 이슈 300–500건, 추정).
