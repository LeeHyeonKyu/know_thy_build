# Factory Audit Hardening Plan (1.2)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One writer at a time; reviews batched by risk (P0 → opus review).

**Goal:** Close the review-bypass path, make gates fail-closed, and wire the declared-but-unimplemented controls found by the 2026-09-14 external audit of `2ab390c` (see `docs/factory/audit/2026-09-14-external-audit.md`), then buy the one cheap experiment the audit asks for.

**Architecture:** Every fix is a script-enforced control (hook, gate, requirement) with a test that pins the audited failure; prose-only controls are either wired into code or their claim is removed from docs. Ordering follows the audit: P0 (bypass) → P1 (gates) → P2 (evidence/cost).

**Spec:** `docs/superpowers/specs/2026-09-10-factory-design.md` (+ ADR-015..022). Findings are numbered as in the audit (H1–H6, M1–M13, P0-1..P2-15).

## Global Constraints
- TDD; every audited failure gets a test that reproduces it before the fix.
- Hooks are defense in depth; permission/graph/requirements are the authority. No new prose-only control.
- No token values in code/logs/comments. `.factory/**` mirrors regenerated by `factory init --upgrade` in every commit; self-mirror test green.
- Fail-closed everywhere: an unreadable/unavailable input never yields GREEN or "proceed".
- Behaviour changes for adopters are documented in ADR-023 (this plan's ADR) with the audit finding id.

### Task 1: P0 — hook normalization, status forgery, protected-list parity (H1a, H1b, M6, M8, M9)
Files: `factory/hooks/block-dangerous.sh`, `factory/hooks/deny-all-writes.sh`, `factory/hooks/check-merge-gate.sh` (+ templates), `factory/test/hooks.test.js`, ADR-023.
- Normalize the command before every rule: join `\⏎` continuations, collapse runs of whitespace, then match the SINGLE resulting string (like deny-all-writes). Table tests: the audit's 6 backslash-newline cases must exit 2; multi-line heredocs that merely mention verbs in a string stay allowed where the existing false-positive guards say so.
- Block `gh api … /statuses/…` (any method), `gh api … /check-runs`, `gh api … /commit/…/status`, and `gh pr review --approve` in agent stages (approval belongs to the merge actor only).
- `check-merge-gate.sh`: reads stdin JSON like the other hooks; if it has no real rule, delete it and its settings entry (no phantom gates).
- Protected-list parity: one source of truth for the protected globs — `harness.toml [protected].factory` — consumed by `block-dangerous.sh` (generated `prot` list at install time via `factory init`) and by ci-settings deny generation; a doctor check `protected.parity` FAILs on drift. Harness mode (`FACTORY_HARNESS_ISSUE=1`): `harness.toml` stays editable ONLY outside `[protected]`, `[gates.thresholds]`, `[load_bearing]` — enforce by L1 section check (integrity policy) so a harness PR touching those sections is human-merge.

### Task 2: P0 — review is verified before merge; human gate is an explicit choice (H1c, H6, M7)
Files: `factory/lib/merge-stage.js`, `factory/lib/requirements.js`, `factory/lib/bootstrap.js`, `factory/cli/bootstrap.js`, templates `factory-merge.yml`, ADR-023.
- Before `mergePr`: require a `review.v1` handoff for the PR head sha with roster-size quorum and all-approve (recomputed from `must_fix` via aggregate, not the handoff's own `decision`), K not exceeded, and `factory/review` status posted by a run whose runner id appears in a heartbeat/handoff of this issue (status author check via `gh api` `creator.login` == bot login when available). Any failure → `factory:needs-human` with the reason, no merge.
- `factory:merged` requirement rule re-checks quorum + all-approve (not only `factory:approved`).
- `FACTORY_TWO_ACTOR=true` and no merge token → the merge job FAILS loudly (no silent fallback to the bot token); single-actor mode keeps the fallback.
- Human gate: `CHARTER.md` gains `merge.human_gate: true|false` (template default `true`); when true, bootstrap sets the `factory-merge` environment `reviewers` to the owner (one required reviewer per merge job) and the merge stage documents it; when false, the CHARTER must state it explicitly (doctor WARN "dark merge: no per-PR human signature"). KTB/demo set `false` explicitly (dark dogfood).

### Task 3: P1 — gates are gates (H2, P1-5/6/7, M3, M4)
Files: `factory/lib/gates.js`, `factory/test/gates.test.js`, `factory/lib/classify-failure.js`, `templates/factory/factory/harness.toml`, `factory/lib/doctor/harness.js`.
- `recomputeStatus`: any `misconfigured` gate → `MISCONFIGURED` (exit 2, status not success); required gates enforced regardless of level list; proof gates (`prove-test`, `new-test-repeat`) are first-class level members so `required` can name them. Flip the tests that pinned the bug.
- Levels must differ: template `fast=[lint,unit]`, `full=[lint,unit,prove-test,new-test-repeat]`, `deep=full+integration/e2e/diff_coverage when configured`; doctor FAILs if `full`/`deep` equal `fast`.
- `lint = "node -e 0"` is a doctor FAIL (`gates.lint-noop`); KTB's own lint becomes `node --check` over changed JS + `yml-lint` over workflows (+ `skill-md` lint).
- Flaky classification: 5/5 base failures = `broken-base` (RED, needs-human "main is red"), not `flaky-existing`; `flaky-existing` capped at `gates.thresholds.flaky_max` (default 2) per PR.
- Quarantine never flips a test the PR touched (test file in the diff) and never flips more than `quarantine.max_effective` per PR.

### Task 4: P1 — test tampering and self-graded tier (H5, H3, M12)
Files: `factory/lib/integrity.js`, `factory/lib/context.js`, `factory/lib/gates.js` (`tierFloor`), `factory/lib/requirements.js`.
- Integrity: deleted or modified lines in existing `test_glob` files (outside pure additions) → `policy` violation (human merge) unless the issue's `done_when` names that test file explicitly (`tests_changed_allowed`).
- `context.js` uses `tier_effective = max(triage tier, tierFloor(diff))` for roster and plan rounds; `tier_effective` recorded in handoffs; `docs` tier excludes `.claude/agents/**`, `templates/**`, `.factory/**`, `.github/**` from `DOC_GLOBS`.
- `[load_bearing].paths` resolved against the installed layout (`.factory/lib/**` for adopters, `factory/lib/**` for KTB) — doctor `load-bearing.paths-exist`.

### Task 5: P2 — cold read wired, loader removed, overlap measured (H4, M5, P2-12/13/14)
Files: `factory/lib/context.js`, `templates/factory/claude/workflows/factory-review.js`, `factory-plan.js`, `factory/lib/retro/harvest.js`, `.factory/roles.toml`.
- Role-filtered context: `buildContext` writes `context.<role>.json` honoring `cold_read` (reviewers never receive `handoffs.implement` verifier verdicts nor `handoffs.plan`; spec-conformance receives the plan `done_when` only). The review workflow reads the role file; a test asserts the implement handoff is absent from every reviewer context.
- Remove the `factory-loader` LLM call: `context.json` carries `model` per role; workflows read it.
- `on_others` aggregation: harvest stats `unique_findings_by_role` and `overlap_ratio`; `factory status`/retro print them.

### Task 6: P2 — triage default-deny, prove-test base env, duplicate-run guard, lessons evidence (M1, M2, M13, M10/M11)
- CHARTER `triage.default = needs-info|ready` (template default `needs-info`; KTB/demo `ready`); NEVER_AUTOMATE items get script re-checks where expressible as globs.
- prove-test: base worktree gets dependency install; `Cannot find module`/import errors on base are `inconclusive` (not proof) — such a PR is not auto-mergeable on that gate.
- Entry-label guard fails closed when the label lookup fails.
- Lessons: `evidence_runs` validated against records-branch run ids; citations incremented when a lesson id appears in a handoff; retirement by citations then age.

### Task 8: P0 — stages run with the factory's own config from base, never the PR head (KTB-37; found by KTB #3 → harness issue #9)
Files: `factory/bin/run-stage.js` (`makeCheckoutHead`), tests, spec §4.2, `docs/factory/audit/response-task-8.md`.
- After checking out PR content, overlay `.factory/**` (except `out/**`), `.claude/**`, `docs/factory/CHARTER.md` from the stage's own commit (`GITHUB_SHA` / base). Fail closed if the overlay fails. Implement commits never include overlaid files.
- Why: a PR head that predates a harness fix can never receive it (live: #3 after KTB-36), and an agent PR editing hooks/settings/reviewer prompts would otherwise run its own review on tampered config.

### Task 9: P2 — plan defaults from the baseline experiment (result of Task 7)
Evidence: `docs/factory/dogfood/2026-09-14-plan-baseline.md` — coverage factory vs single-pass: #8 —/—, #2 0.44 vs 0.31, #15 0.67 vs 1.00, #18 0.33 vs 1.00; cost 5.4× per pass, 33.7× per issue; 5/15 must_fix items were created by the plan's own guard-shaped done_when.
- Default plan = single opus pass + one skeptic pass (2 calls). The 4-role debate (R1/R2/signing) runs only for `load-bearing` tier (first persistent write path / first public wire contract / protected change) — charter `plan.debate_tiers = ["load-bearing"]`.
- Plan validator: (a) a risk recorded in `dissent_log` without a matching `done_when` is rejected (the #2 9-round/$118 root cause); (b) `done_when` ≤ 6 items; (c) guard-shaped done_when (whitelists, ordering, regexes over the repo) rejected unless the issue asks for a guard.
- Record in ADR-023 with the decision rule outcome (2.5/4 strict → not fired; adopted anyway on cost + self-inflicted must_fix evidence; revisit at n≥10).

### Task 7: P2 — the one experiment (P2-10/11)
- Script `factory/bin/plan-baseline.js`: run a single-agent plan (opus, one pass + skeptic) for a given issue offline against the records of #8/#2/#15/#18 (demo) and diff `done_when` vs actual review `must_fix`; write `docs/factory/dogfood/2026-09-14-plan-baseline.md`. Cost ceiling: 4 plans ≈ $12 each — owner-visible in the report. Decision rule recorded in ADR-023: if baseline done_when ⊇ must_fix on ≥3/4 issues, plan R2 + signing rounds are removed from the default.
- Cross-provider reviewer (P2-15): documented as an owner decision (needs a second provider key) — not implemented here.
