# Dogfood — `know_thy_build` self-adoption (Plan 6 Task 5, LOCAL part)

사람이 읽는 관찰 기록이다(retro가 아니다). Task 5는 브랜치 `spec/factory-1.0` 위에서 KTB 자신을 브라운필드로
factory에 태우는 시험(P6-R3): `harness.toml`(M0) → CHARTER(ready) → `factory init`(자기 자신의 템플릿으로) →
`factory doctor` 전체. 원격 다크 실행(bootstrap·이슈 다크 처리·사람 머지 관찰)은 이 리포의 factory 파일이
`spec/factory-1.0`에만 있고 기본 브랜치(`main`)에는 없어 GitHub Actions가 이 워크플로들을 아직 돌릴 수
없으므로 **PARKED**(아래 참조) — Task 5는 여기서 "로컬 준비"까지다.

- **대상**: `know_thy_build` 자기 자신, 브랜치 `spec/factory-1.0` (BASE 5d1c8a4, 이 커밋으로 갱신).
- **환경**: macOS 15(Darwin 24.6), Node 24.14(로컬) / 저장소 선언은 Node 22.

### 발견된 결함
KTB-12(#8 참조): `.gitignore`가 `.claude/commands/`를 통째로 무시해 `factory init`이 설치한 `.claude/commands/factory-*.md` 디스패처 5개가 커밋되지 않고 있었다 — CI 체크아웃에는 없는 파일이 되어 모든 `claude -p /factory-<stage>` 호출이 실패했을 결함. 그 외에는 init이 기존 `.claude/settings.json`을 정상 병합했고, `.factory/harness.toml`/`docs/factory/CHARTER.md`를 보존했으며, `[commands]`가 실제로 실행되어 스모크·전체 유닛 게이트가 통과했다. Task 1(데모)·Task 3(#2)·Task 4(#8) 경로에서 이미 고쳐진 KTB-1~KTB-11이 여기서도 함께 검증된 셈이다(같은 코드 경로: `factory init`, `factory doctor`).

### 컨트롤러 판결 — KTB 자신의 `[protected].factory`
KTB의 소스(`factory/**`, `templates/**`, `bin/**`)는 이 저장소에서는 "애플리케이션 코드"가 아니라 **빌드/게이트 설정 그 자체**다: `harness.toml [commands]`의 모든 게이트 명령이 `factory/**` 아래 코드로 해석되고, `templates/**`는 다른 모든 채택 저장소의 `.factory/`·`.claude/`·CI가 찍혀 나오는 원본이다. 따라서 P6-R3("KTB 개발 이슈는 사람 머지")을 harness.toml 수준에서 실체화하려면 이 세 글롭을 `[protected].factory`에 추가해야 한다 — 그래야 이들을 건드리는 PR이 ADR-020 KTB-5/KTB-6의 L1 merge-stage 경로(자동 머지 거부 → `factory:needs-human`)를 타고, L0 `integrity` 체크는 그것을 위반이 아니라 정보성 항목으로만 남긴다. `harness.toml`의 `[protected]` 섹션 주석에 이 판결을 기록했다.

### PARKED — 원격 다크 실행 (사용자 조치 필요)
Task 5 brief의 "다크 처리 → factory 파일이 diff에 포함되면 integrity RED → 사람 머지 경로 관찰"은 **원격에서** 일어나는 일이다: GitHub Actions는 `issues:` 트리거 워크플로를 저장소의 **기본 브랜치**(`main`)에서 읽는데, 이번에 만든 `.github/workflows/factory-*.yml`·`.factory/**`·`.claude/**`는 전부 `spec/factory-1.0`에만 있고 `main`에는 없다. 사용자는 "KTB를 push/merge하지 말라"고 명시했으므로(이 세션의 하드 제약), 원격 실행은 이 세션에서 불가능하다.

다크 실행을 완주하려면 사용자가 직접:
1. `spec/factory-1.0`을 `main`으로 병합(또는 `main`에서 이 커밋을 체리픽 — KTB 자신의 스펙/코드 브랜치 정책에 맞는 방식으로)한다.
2. `factory bootstrap`을 KTB repo(`LeeHyeonKyu/know_thy_build` 추정)에서 실행해 라벨·(가능하면) branch protection을 건다.
3. `FACTORY_BOT_TOKEN`·`CLAUDE_CODE_OAUTH_TOKEN` 시크릿을 등록한다.
4. 이슈 1건(예: "doctor 출력에 `--json`의 summary 정렬" — brief 예시)을 만들어 큐에 넣고, factory 파일이 diff에 포함된 PR이 `factory/integrity`에서 informational로만 걸리고 merge 스테이지가 `factory:needs-human`으로 넘기는지 관찰한다.

이 로그와 `harness.toml`/`CHARTER.md`/`init`/`doctor` 결과는 그 실행을 위한 로컬 준비가 전부 끝났음을 보여준다. own-calendar(Task 6)와 동일한 종류의 파킹(사용자 시크릿·저장소 조치가 필요한 마지막 단계)이며, ADR-020의 샘플 크기 메모에 함께 기록한다.
