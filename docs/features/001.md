# docs 디렉토리 구조 전환

생성 문서를 루트가 아닌 `docs/` 디렉토리에 모으고, 기존 유저를 자동 migration한다.

## What

know-thy-build가 생성하는 모든 문서(`PROJECT.md`, `TECHNICAL.md`, `features/`)의 경로를 `docs/` 하위로 변경한다. 기존에 루트에 파일이 있는 유저는 slash command 실행 시 자동으로 `docs/`로 migration되며, CLAUDE.md의 경로 참조도 함께 업데이트된다.

## Why

루트 디렉토리에 `PROJECT.md`, `TECHNICAL.md`, `features/` 가 쌓이면 프로젝트 자체 파일과 섞여 지저분해진다. `docs/`로 모으면 프로젝트 구조가 깔끔해지고, 생성 문서의 성격이 명확해진다.

## Scope

**Includes:**
- 템플릿이 `docs/` 경로를 참조하도록 변경
- slash command 실행 시 루트에 기존 파일 감지 → `docs/`로 이동 (default, 사용자 확인)
- CLAUDE.md 내 경로 참조 업데이트
- `docs/` 먼저 탐색, 루트는 fallback

**Excludes:**
- 사용자 지정 디렉토리 선택 (고정 `docs/`)
- npx 설치 시점 migration (slash command 시점에서 처리)

## Done When

- [ ] 새로 생성되는 문서가 `docs/` 하위에 떨어진다
- [ ] 루트에 기존 파일이 있으면 감지하여 `docs/`로 이동을 제안하고, default로 이동한다
- [ ] migration 시 CLAUDE.md의 경로 참조도 함께 업데이트된다
- [ ] 세 개 템플릿(project, technical, feature) 모두 `docs/` 경로를 우선 탐색한다

## Approach

- 세 개 템플릿 `.md` 파일에 migration 감지 로직을 프롬프트로 추가
- 탐색 순서: `docs/PROJECT.md` → `PROJECT.md` (fallback)
- migration은 대화 시작 전에 처리하고, 본래 대화로 진입
