# docs directory restructuring

Consolidate generated documents under the `docs/` directory instead of the project root, with automatic migration for existing users.

## What

Change the path of all documents generated by know-thy-build (`PROJECT.md`, `TECHNICAL.md`, `features/`) to live under `docs/`. Users with existing files at the root are automatically migrated when running a slash command, and CLAUDE.md path references are updated accordingly.

## Why

When `PROJECT.md`, `TECHNICAL.md`, and `features/` accumulate at the project root, they mix with the project's own files and create clutter. Moving them under `docs/` keeps the project structure clean and makes the nature of generated documents explicit.

## Scope

**Includes:**
- Update templates to reference `docs/` paths
- Detect existing files at root on slash command execution → offer to move to `docs/` (default: move)
- Update path references in CLAUDE.md
- Search `docs/` first, root as fallback

**Excludes:**
- User-specified directory choice (fixed to `docs/`)
- Migration at npx install time (handled at slash command execution time)

## Done When

- [x] Newly generated documents land under `docs/`
- [x] Existing files at root are detected and offered to move to `docs/` (default: move)
- [x] CLAUDE.md path references are updated during migration
- [x] All three templates (project, technical, feature) search `docs/` path first

## Approach

- Add migration detection logic as prompts in the three template `.md` files
- Search order: `docs/PROJECT.md` → `PROJECT.md` (fallback)
- Handle migration before the conversation starts, then proceed to the main dialogue
